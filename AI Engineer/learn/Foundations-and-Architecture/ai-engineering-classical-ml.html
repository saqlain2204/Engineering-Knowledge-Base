Classical Machine Learning from Zero

The ideas every model is built on, before neural networks. We train real models, measure them the right way, and catch the mistakes that make good-looking results false. Every number on this page comes from a real run you can repeat.

1. What Machine Learning Is

In normal programming, you write the rules. In machine learning, you give the computer examples, and it finds the rules by itself.

Intuition: A child learns what a dog is by seeing many dogs, not by reading a definition. A model learns the same way. It sees many examples with answers, and slowly adjusts itself until its guesses match the answers.

A few words you will see everywhere:

WordPlain meaningExample (house prices)
Example (or sample, row)One thing we know aboutOne house
FeatureA number that describes the example (an input)Size in square metres, number of rooms
Label (or target)The answer we want to predictThe sale price
ModelA formula with adjustable numbers insideprice = w × size + b
Parameters (or weights)The adjustable numbers the model learnsw and b
TrainingAdjusting the parameters so predictions match labelsFinding good w and b
LossOne number that says how wrong the model is. Lower is better.Average squared error in price
Inference (or prediction)Using the trained model on new examplesPricing a house that is not sold yet

Neural networks and large language models use the same ideas. They just have far more parameters. See Foundations for the neural network version.

2. Kinds of Problems

  • Regression: the label is a number. "What will this house sell for?"
  • Classification: the label is a category. "Is this email spam or not?" "Is this tumour malignant or benign?"
  • Supervised learning: every training example has a label. Both problems above are supervised.
  • Unsupervised learning: no labels. The model finds structure by itself, for example grouping customers into clusters.

This page covers supervised learning, because most real work starts there.

3. Linear Regression and Gradient Descent

3.1 The model

Linear regression draws the best straight line through the data. With one feature \(x\), the model is:

\[ \hat{y} = w x + b \]

Here \(\hat{y}\) ("y hat") is the prediction, \(w\) is the slope (how much \(\hat{y}\) grows when \(x\) grows by 1), and \(b\) is the bias (the value when \(x = 0\)).

3.2 The loss: mean squared error

For each example, the error is prediction minus truth. We square it (so negative and positive errors do not cancel, and big errors count more) and take the average. This is the mean squared error (MSE):

\[ L = \frac{1}{n}\sum_{i=1}^{n} (\hat{y}_i - y_i)^2 \]

3.3 Gradient descent, step by step

Intuition: You stand on a foggy hill and want to reach the lowest point. You cannot see far. So you feel which way the ground slopes under your feet, and take a small step downhill. Repeat. The "slope under your feet" is the gradient. The step size is the learning rate.

The gradient tells us how the loss changes when we nudge each parameter. For MSE, calculus gives:

\[ \frac{\partial L}{\partial w} = \frac{2}{n}\sum_i (\hat{y}_i - y_i)\,x_i \qquad \frac{\partial L}{\partial b} = \frac{2}{n}\sum_i (\hat{y}_i - y_i) \]

Then we move each parameter a little against its gradient (downhill):

\[ w \leftarrow w - \eta \frac{\partial L}{\partial w} \qquad b \leftarrow b - \eta \frac{\partial L}{\partial b} \]

\(\eta\) ("eta") is the learning rate.

3.4 Worked example by hand

Data: four points that lie exactly on the line \(y = 2x + 1\). So we know the right answer is \(w = 2, b = 1\). Let us see if gradient descent finds it.

x1234
y3579

Start with \(w = 0, b = 0\) and learning rate \(\eta = 0.05\).

  1. Predict. Every prediction is 0.
  2. Errors (prediction minus truth): \(-3, -5, -7, -9\).
  3. Loss: \((9 + 25 + 49 + 81)/4 = 41\).
  4. Gradient for w: error × x gives \(-3, -10, -21, -36\). The mean is \(-17.5\). Times 2 is \(-35\).
  5. Gradient for b: mean error is \(-6\). Times 2 is \(-12\).
  6. Update: \(w = 0 - 0.05 \times (-35) = 1.75\). \(b = 0 - 0.05 \times (-12) = 0.6\).

One step took us from loss 41 to loss 1.1288. Here is the real run of the same loop (code below):

step 1: w=0.0000 b=0.0000 loss=41.0000 dw=-35.0000 db=-12.0000
step 2: w=1.7500 b=0.6000 loss=1.1288 dw=-5.7500 db=-2.0500
step 3: w=2.0375 b=0.7025 loss=0.0433 dw=-0.9250 db=-0.4075
step 10: w=2.0851 b=0.7498 loss=0.0105 dw=0.0255 db=-0.0749
step 100: w=2.0219 b=0.9356 loss=0.0007 dw=0.0066 db=-0.0193
step 1000: w=2.0000 b=1.0000 loss=0.0000 dw=0.0000 db=-0.0000
import numpy as np
x = np.array([1.0, 2.0, 3.0, 4.0]); y = np.array([3.0, 5.0, 7.0, 9.0])
w, b, lr = 0.0, 0.0, 0.05
for step in range(1, 1001):
    err = (w * x + b) - y
    loss = (err ** 2).mean()
    dw = 2 * (err * x).mean()
    db = 2 * err.mean()
    w -= lr * dw
    b -= lr * db
print(w, b)   # 2.0 1.0 (rounded)

Notice: after step 3, \(w\) is already a bit above 2 while \(b\) is still too small. The two parameters trade off, and slowly settle. This "zig-zag then settle" is normal.

3.5 The learning rate matters a lot

Same data, 100 steps, three learning rates (real run):

Rule: if your loss goes up or becomes nan (not a number), lower the learning rate first.

4. Logistic Regression: Predicting Yes or No

For classification we want a probability between 0 and 1, not any number. Logistic regression takes the same straight-line score \(z = w \cdot x + b\) and squashes it with the sigmoid function:

\[ \sigma(z) = \frac{1}{1 + e^{-z}} \]

Score z-2024
\(\sigma(z)\)0.11920.50.88080.9820

Big positive score means "very likely yes". Big negative score means "very likely no". Then we pick a threshold (often 0.5): above it, predict yes.

Loss: log loss (cross-entropy)

If the true label is 1 and the model says probability \(p\), the loss is \(-\ln p\). If the true label is 0, the loss is \(-\ln(1-p)\).

  • True label 1, model says 0.9: loss = \(-\ln 0.9 = 0.105\). Small, good.
  • True label 1, model says 0.5: loss = 0.693.
  • True label 1, model says 0.1: loss = 2.303. Confident and wrong is punished hard.

Training uses gradient descent again, just with this loss. Large language models use the same loss to predict the next token, only with many classes instead of two.

5. Train, Validation, Test, and Overfitting

Intuition: If a teacher gives you the exact exam questions to practise, you can score 100% by memorising answers without learning anything. To know if a student really learned, you test on new questions. Models are the same.

So we split the data into three parts:

  • Training set: the model learns from it.
  • Validation set: we use it to make choices (which model, which settings). The model never trains on it.
  • Test set: touched once, at the very end, to report the final score. If you keep checking it and tweaking, it slowly becomes a second validation set and your score becomes too optimistic.

Overfitting, seen in a real run

6. Cross-Validation

With little data, one validation split is noisy: you might get lucky or unlucky. k-fold cross-validation fixes this. Split the training data into k equal parts (folds). Train k times. Each time, hold out a different fold for validation. Average the k scores.

5-fold cross-validation (V = validation fold, T = train)
round 1:  V T T T T
round 2:  T V T T T
round 3:  T T V T T
round 4:  T T T V T
round 5:  T T T T V   -> report mean and spread of the 5 scores

Real run on the breast cancer dataset (details in the next section), 5 folds of the 426 training rows:

5-fold CV [0.9767 0.9765 0.9765 0.9882 0.9647] mean 0.9765 std 0.0074

The spread (standard deviation 0.0074) tells you how much the score moves just from which rows land in which fold. Differences between two models smaller than this are probably noise.

7. Measuring a Classifier

7.1 The dataset

We use the Wisconsin breast cancer dataset that ships with scikit-learn: 569 tumours, 30 measured features each (radius, texture, area, and so on), 212 malignant and 357 benign. We call malignant the positive class, because that is the case we must not miss. We keep 25% (143 rows, 53 malignant) as a test set and train logistic regression on the rest.

7.2 Accuracy can lie

A "model" that always says benign gets 62.94% accuracy on this test set (real run), while catching zero cancers. When one class is more common, accuracy alone is misleading. This is called class imbalance.

7.3 The confusion matrix

Count the four possible outcomes:

Predicted positivePredicted negative
Actually positiveTP (true positive): caught itFN (false negative): missed it
Actually negativeFP (false positive): false alarmTN (true negative): correctly ignored

From these four counts:

  • Precision = TP / (TP + FP). "When the model says positive, how often is it right?"
  • Recall = TP / (TP + FN). "Of all real positives, how many did we catch?"
  • F1 = 2 × precision × recall / (precision + recall). One number that is high only when both are high.

7.4 Real results, and the threshold trade-off

The model outputs a probability. Changing the threshold moves the balance between misses and false alarms (real run on the 143 test rows):

ThresholdTPFPFNTNAccuracyPrecisionRecallF1
0.54914890.96500.98000.92450.9515

Check one row by hand (threshold 0.5): precision = 49 / (49 + 1) = 0.98. Recall = 49 / (49 + 4) = 0.9245. F1 = 2 × 49 / (2 × 49 + 1 + 4) = 98 / 103 = 0.9515.

Lowering the threshold catches more cancers (recall up) but raises more false alarms (precision down). Which is right depends on the cost of each mistake. For a screening test, a miss is far worse than a false alarm, so a low threshold is reasonable. For a spam filter, a false alarm (losing a real email) is the worse mistake.

Careful: we picked thresholds while looking at the test set here, only to teach. In a real project, choose the threshold on the validation set, then report the test score once.

7.5 ROC-AUC: one number for all thresholds

The ROC curve plots recall (also called the true positive rate) against the false positive rate, FP / (FP + TN), for every possible threshold. AUC is the area under that curve. It has a simple meaning: pick one random positive and one random negative example; AUC is the chance the model gives the positive one a higher score. 0.5 is coin-flipping, 1.0 is perfect. Our model's test AUC is 0.9962.

8. Feature Scaling

In this dataset, "mean area" is in the hundreds or thousands, while "mean smoothness" is around 0.1. Gradient descent then struggles: one direction of the hill is steep and another is almost flat, so steps that suit one direction are wrong for the other.

Standardisation fixes this. For each feature, subtract its mean and divide by its standard deviation, so every feature has mean 0 and spread 1:

\[ x' = \frac{x - \text{mean}}{\text{std}} \]

Real run, same split: without scaling, logistic regression hit its limit of 100 optimisation steps without finishing (scikit-learn warns about this) and scored 0.9441 test accuracy. With scaling it finished and scored 0.9650.

Important: compute the mean and std on the training data only, then apply the same numbers to validation and test data. A scikit-learn Pipeline does this for you.

9. Data Leakage: the Silent Result Killer

Data leakage means information from the validation or test data sneaks into training. Scores look great, then the model fails in real use.

A real experiment with pure noise

We made 100 rows of 5,000 random features, and random 0/1 labels. There is nothing to learn, so honest accuracy should be about 50%.

  • Wrong way: pick the 20 features most related to the label using all 100 rows, then run 5-fold cross-validation. Result: 0.91 accuracy.
  • Right way: put feature selection inside the cross-validation, so each fold picks features using only its own training rows. Result: 0.47 accuracy.

Why? With 5,000 random features, some will match the labels by pure chance. Picking them while looking at the validation rows means the validation rows already "voted" for those features.

Other common leaks:

  • Scaling or filling missing values using statistics from all data before splitting.
  • Features that are only known after the event, such as "refund issued" when predicting "will the customer complain".
  • The same person, patient, or document in both train and test (split by group, not by row).
  • Time series split randomly, so the model trains on the future and is tested on the past. Split by time instead.

10. The Full Recipe in Code

This is the code that produced the numbers above (scikit-learn 1.9.1, NumPy 2.5.5):

import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split, cross_val_score
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline
from sklearn.metrics import confusion_matrix, precision_score, recall_score, roc_auc_score

data = load_breast_cancer()
X, y = data.data, 1 - data.target          # make malignant = 1 (positive)

# 1. split once, keep the test set locked away
X_tr, X_te, y_tr, y_te = train_test_split(
    X, y, test_size=0.25, random_state=42, stratify=y)   # stratify keeps class ratio

# 2. pipeline = scaling + model, so scaling is learned from training folds only
model = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))

# 3. compare choices with cross-validation on the training set
print(cross_val_score(model, X_tr, y_tr, cv=5).mean())

# 4. train on all training data, evaluate once on the test set
model.fit(X_tr, y_tr)
p = model.predict_proba(X_te)[:, 1]          # probability of malignant
pred = (p >= 0.5).astype(int)
print(confusion_matrix(y_te, pred).ravel())  # tn, fp, fn, tp
print(precision_score(y_te, pred), recall_score(y_te, pred), roc_auc_score(y_te, p))
  1. Look at the data first: sizes, class counts, missing values.
  2. Split. Lock the test set away.
  3. Build a simple baseline (always predict the common class, or a plain linear model).
  4. Choose metrics that match the real cost of mistakes.
  5. Try improvements, compare with cross-validation.
  6. Pick the threshold on validation data.
  7. Report the test score once.

11. Common Pitfalls

  • Reporting accuracy on imbalanced data. Always show the confusion matrix, precision, and recall.
  • Tuning on the test set. Your reported number becomes too good to be true.
  • Preprocessing before splitting. Causes leakage. Use pipelines.
  • Ignoring convergence warnings. The model did not finish training. Scale features or raise the step limit.
  • Trusting tiny differences. A 0.3% gain is noise if cross-validation scores move by 0.7%.
  • Skipping the baseline. Without it you cannot tell if 90% is good or bad.

12. Practice Problems (with Solutions)

Problem 1: one gradient step

Data: x = [1, 2], y = [2, 4]. Start at w = 0, b = 0, learning rate 0.1. What are w and b after one step?

Solution

Predictions are 0, 0. Errors are -2, -4. Gradient for w = 2 × mean(-2 × 1, -4 × 2) = 2 × mean(-2, -8) = 2 × (-5) = -10. Gradient for b = 2 × mean(-2, -4) = -6. New w = 0 - 0.1 × (-10) = 1.0. New b = 0 - 0.1 × (-6) = 0.6.

Problem 2: precision and recall

A fraud model flags 40 transactions. 30 are really fraud. There were 50 frauds in total. Find precision, recall, and F1.

Solution

TP = 30, FP = 40 - 30 = 10, FN = 50 - 30 = 20. Precision = 30/40 = 0.75. Recall = 30/50 = 0.60. F1 = 2 × 0.75 × 0.60 / (0.75 + 0.60) = 0.9 / 1.35 = 0.667.

Problem 3: diagnose the curve

Training accuracy is 99%. Validation accuracy is 71%. What is happening, and name two fixes.

Solution

Overfitting: the model memorised the training data. Fixes: a simpler model (fewer features, lower degree), stronger regularisation (a penalty on large weights), or more training data.

Problem 4: spot the leak

To predict whether a hospital patient will be readmitted, a team uses the feature "number of days in the follow-up ward". Their validation score is excellent. What is wrong?

Solution

Days in the follow-up ward are only known after the patient comes back, which is the thing being predicted. The feature leaks the answer. At prediction time it does not exist, so the model will fail in practice. Only use features available at the moment you make the prediction.

Problem 5: pick the metric

You build a model that decides which support tickets to escalate to a senior engineer. Senior time is expensive, and a wrongly escalated ticket wastes an hour. A missed urgent ticket is fixed the next day by the normal queue. Which metric should you watch most?

Solution

Precision. False positives (wrong escalations) are the costly mistake, so you want "when we escalate, we are right" to be high. Keep a reasonable recall floor so urgent tickets are not all missed.
