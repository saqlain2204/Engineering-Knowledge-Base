Unsupervised Learning: Clustering, PCA & Anomaly Detection

Most data in the real world has no labels. Nobody has marked which customers are "bargain hunters", which support tickets are about the same bug, or which server log line is the strange one. Unsupervised learning finds structure in data with no answers given. This page builds the three workhorse tools from zero: k-means clustering, PCA, and anomaly detection. It continues from Classical ML from Zero and Trees & Ensembles, and every number comes from a run you can repeat (scikit-learn 1.9, NumPy 2.5).

1. The Idea: Finding Shape With No Answers

In supervised learning, every training row has an answer (a label): "this email is spam", "this house sold for 80 lakh". The model learns to predict the answer.

In unsupervised learning, there are no answers. You only have the rows. The goal is to find useful structure:

  • Clustering: which rows are alike? (Group customers by behavior. Group news articles by topic.)
  • Dimensionality reduction: can we describe each row with fewer numbers and lose little? (Draw 64-column data on a 2D chart. Speed up later models.)
  • Anomaly detection: which rows do not fit in? (Fraud. Broken sensors. Attacks.)

Intuition. Pour a bag of mixed buttons on a table. Nobody tells you the categories, but you can still sort them into piles by size and color (clustering), notice that size and weight tell you almost the same thing so you only need one of them (dimensionality reduction), and spot the one coin that got mixed in (anomaly detection).

The hard part: with no labels, there is no simple "accuracy" to check. You need other ways to judge the result, and in the end a human must decide if the groups make sense.

2. The Words, in Plain English

  • Feature. One column of input, like age or income.
  • Point. One row, seen as a dot in space. Two features make a 2D point; 64 features make a 64D point.
  • Distance. How far apart two points are. Usually straight-line (Euclidean) distance: for (1,1) and (4,5) it is \(\sqrt{3^2+4^2}=5\).
  • Cluster. A group of points that are close to each other.
  • Centroid. The center of a cluster: the average of its points, column by column.
  • Inertia (or within-cluster sum of squares). For every point, take the squared distance to its own centroid, and add them all up. Smaller means tighter clusters.
  • Variance. How spread out a column is: the average squared distance from its mean.
  • Component (in PCA). A new axis, made by mixing the old columns, chosen to capture as much spread as possible.
  • ARI (adjusted Rand index). A score for comparing a clustering with true labels when we happen to have them, used here only to check our work. 1.0 is a perfect match; about 0 is no better than random.

3. K-Means, Worked by Hand

K-means splits the data into k clusters. You choose k. The algorithm is only four steps:

  1. Pick k starting centroids.
  2. Assign: put each point in the cluster of its nearest centroid.
  3. Update: move each centroid to the average of its points.
  4. Repeat steps 2 and 3 until nothing changes.

It is trying to make the inertia as small as possible:

\[ \text{inertia} = \sum_{i=1}^{n} \lVert x_i - \mu_{c(i)} \rVert^2 \]

where \(x_i\) is point i, \(c(i)\) is its cluster, and \(\mu_{c(i)}\) is that cluster's centroid.

Round 2, assign. B is now 1.25 from c1 and about 52.8 from c2, so B moves to c1. D, E, F stay with c2. Inertia = 20.69.

Round 2, update. c1 = average of A, B, C = (1.33, 1.33). c2 = average of D, E, F = (8.33, 8.33).

Round 3. Nobody changes cluster, so the centroids do not move. Done. Final inertia = 2.67. Our code got exactly these numbers: 284, then 20.688, then 2.667, then "converged".

Each round can only lower the inertia or keep it the same: assigning to the nearest centroid cannot make a point's distance worse, and the average is the point that minimizes squared distance to a group. So k-means always stops. But it may stop at a local best, not the best possible split. Section 5 deals with that.

4. How Many Clusters? Elbow and Silhouette

K-means needs k up front. More clusters always lower inertia (with k = number of points, inertia is 0), so you cannot just pick the k with the lowest inertia. Two common checks:

  • Elbow: plot inertia against k. It drops fast while each new cluster splits a real group, then flattens. The bend (the "elbow") is a good k.
  • Silhouette: for each point, let a = its average distance to points in its own cluster, and b = its average distance to points in the nearest other cluster. Its score is \(s = \frac{b - a}{\max(a, b)}\). Near 1: well inside its cluster. Near 0: on a border. Below 0: probably in the wrong cluster. Average over all points; higher is better.

5. Starting Points Matter: k-means++

If two starting centroids land in the same real group, k-means may split that group in two and merge two others, then get stuck. The fix used everywhere today is k-means++: pick the first centroid at random from the data, then pick each next one with a chance that grows with its squared distance from the centroids chosen so far. Far-away points are likely picks, so the starts spread out.

We ran k-means on the same 600 points with k = 4, one start each, 100 different random seeds:

Start methodRuns within 1% of the best inertia (1,127)Worst inertia
Random points58 / 10014,161
k-means++100 / 1001,127

With random starts, 42 runs out of 100 got stuck in a worse answer, the worst one 12 times worse. scikit-learn uses k-means++ by default and also runs several starts (n_init) and keeps the best. Keep both on.

6. Scale Your Features First

K-means uses distance, and distance is ruled by the column with the biggest numbers. We made 400 people: half aged about 25, half aged about 55. Income is random noise around 60,000 (spread 15,000) and has nothing to do with the groups.

person   age   income       distance between two people is about
  1       24   71,200       sqrt( (age diff)^2 + (income diff)^2 )
  2       57   58,900       sqrt( 33^2 + 12,300^2 )  =  about 12,300
                            the age difference barely counts
Input to k-means (k = 2)ARI against the true age groups
Raw age and income-0.002 (no better than random)
Both standardized (mean 0, spread 1)1.000 (perfect)

Without scaling, k-means split people by meaningless income noise. After StandardScaler (subtract each column's mean, divide by its standard deviation), age could finally count, and the split was perfect. Always scale before k-means, PCA, or anything that uses distance. (Tree models do not need it; see feature scaling.)

7. When K-Means Fails: DBSCAN

K-means assumes clusters are round blobs of similar size, because each point simply joins its nearest center. Data shaped like two interlocking crescent moons breaks it:

   . . . .                      k-means draws a straight border
 .         .                    through the middle, cutting
.     A     .     . . . .       each moon in half
             .  .         .
              ..     B     .
                 . . . .

DBSCAN (density-based clustering) works differently. It says: a point is in a dense area if at least min_samples points lie within distance eps of it. Dense points that are close chain together into one cluster, whatever its shape. Points in no dense area are labeled noise (cluster -1). You do not choose k; DBSCAN finds it.

400 points in two moonsARIClusters found
k-means, k = 20.2742 (wrong split)
DBSCAN, eps = 0.2, min_samples = 51.0002, with 0 noise points

The cost: you must pick eps, and one eps fails when clusters have very different densities. HDBSCAN (in scikit-learn as HDBSCAN) tries many densities at once and is often the better default for messy real data.

8. PCA: Squeezing Many Columns Into Few

Many data sets have far more columns than they need. A tiny 8×8 picture of a digit has 64 pixel columns, but neighboring pixels move together. Height in cm and height in inches are the same information twice.

PCA (principal component analysis) finds new axes that follow the data's spread:

  • The first component (PC1) is the direction in which the points are most spread out.
  • The second (PC2) is the most spread-out direction at a right angle to PC1. And so on.
  • Keep only the first few components and throw away the rest. You lose the directions with little spread, which are often just noise.
  y                                     the cloud is long and thin
  |              . .  .                 PC1 runs along its length
  |          . .  . .     PC1 --->      PC2 runs across it
  |      . .  . .                       keeping only PC1 turns each
  |   . .  .                            2D point into one number, and
  |  .  .        PC2 (short)            loses only the small sideways
  +-------------------------- x         wiggle

Each component comes with an explained variance ratio: the share of the total spread it captures. If the first 2 components explain 95%, a 2D chart shows almost everything.

9. PCA, Worked by Hand

Five points: (2,1), (3,4), (4,3), (5,6), (6,5).

Step 1: center. The mean is (4, 3.8). Subtract it: (-2,-2.8), (-1,0.2), (0,-0.8), (1,2.2), (2,1.2).

Step 2: covariance matrix. Variance of x = (4+1+0+1+4)/4 = 2.5. Variance of y = (7.84+0.04+0.64+4.84+1.44)/4 = 3.7. Covariance (how x and y move together) = ((-2)(-2.8) + (-1)(0.2) + 0 + (1)(2.2) + (2)(1.2))/4 = (5.6 - 0.2 + 2.2 + 2.4)/4 = 2.5. (We divide by n - 1 = 4, the usual sample formula.)

\[ C = \begin{pmatrix} 2.5 & 2.5 \\ 2.5 & 3.7 \end{pmatrix} \]

Step 3: eigenvalues. The components are the eigenvectors of C: directions that C only stretches, never turns. The stretch amounts (eigenvalues) are the variance along each direction. For a 2×2 matrix, solve \(\lambda^2 - (\text{trace})\lambda + \det = 0\). Trace = 2.5 + 3.7 = 6.2. Determinant = 2.5 × 3.7 - 2.5 × 2.5 = 3.0.

\[ \lambda = \frac{6.2 \pm \sqrt{6.2^2 - 4 \times 3.0}}{2} = \frac{6.2 \pm 5.142}{2} \;\Rightarrow\; \lambda_1 = 5.671,\; \lambda_2 = 0.529 \]

Step 4: explained variance. PC1 explains 5.671 / (5.671 + 0.529) = 91.5%. PC2 explains 8.5%.

Step 5: direction of PC1. Solve \((C - 5.671 I)v = 0\): the first row gives \(-3.171 v_x + 2.5 v_y = 0\), so \(v_y = 1.268 v_x\). Scale to length 1: v = (0.619, 0.785). It points up and to the right, along the cloud.

Step 6: project. Each point's new single number is its dot product with v. For (-2, -2.8): 0.619 × (-2) + 0.785 × (-2.8) = -3.437. All five: -3.437, -0.462, -0.628, 2.347, 2.181. We went from 2 numbers per point to 1 and kept 91.5% of the spread. NumPy's eigh gave exactly these values.

For pictures of high-dimensional data, t-SNE and UMAP usually show clusters more clearly than PCA, because they keep near neighbors near. But distances between far-apart clusters in those pictures mean little, and cluster sizes can be misleading. Use them to look, not to measure.

11. Anomaly Detection

An anomaly (or outlier) is a point that does not look like the rest. Three ways to find them, from simplest to strongest:

  • Z-score per column. How many standard deviations from the mean? A request that took 9 seconds when the mean is 0.2 s and the standard deviation is 0.1 s has z = (9 - 0.2) / 0.1 = 88. Flag anything above, say, 4. Simple, but it looks at one column at a time and is fooled by data that is not bell-shaped.
  • Distance to the nearest cluster. Run k-means; points far from every centroid are odd.
  • Isolation Forest. Build many random trees that split the data at random places. A normal point sits in a crowd and needs many splits to be cut off alone. An odd point is cut off in just a few splits. A short average path means "anomaly". It works on many columns at once and scales well.

Real run

500 normal points in 3 blobs, plus 10 random points spread over a wide square. Isolation Forest with contamination=0.02 (we expect about 2% anomalies):

FlaggedTrue anomalies among themMissed
119 of 101

It caught 9 of the 10 planted points and wrongly flagged 2 normal ones on the edges of blobs. The missed point was random; one that happens to land near a blob looks normal to any method. In real systems, anomaly scores are a ranking for a human to review, not a final verdict. contamination just sets where the cut-off goes.

12. Today's Big Use: Clustering Embeddings

An embedding turns text (or an image) into a list of numbers, often 384 to 3,072 of them, so that similar meanings get nearby vectors. Put that together with this page and you get some of the most common jobs in AI teams today:

  • Topic discovery. Embed 50,000 support tickets, cluster them, and read 10 examples from each cluster. You find "password reset loop" and "invoice in wrong currency" without anyone labeling anything. Tools like BERTopic do exactly this: embeddings, then UMAP to shrink the dimensions, then HDBSCAN to cluster.
  • Cleaning training data. Near-duplicate prompts in an LLM fine-tuning set make the model memorize. Cluster the embeddings and keep a few examples per tight cluster.
  • Choosing evaluation cases. Cluster real user questions and sample from every cluster, so your eval set covers rare kinds of questions too (see Evaluation).
  • Spotting drift. If many new queries fall far from every existing cluster, users are asking about something new, and your RAG index or prompts may not cover it.

Two practical rules for embeddings. First, most embedding models are meant to be compared with cosine similarity (the angle between vectors). If you scale every vector to length 1 first, plain Euclidean k-means gives the same grouping as clustering by cosine. Second, with hundreds of dimensions, it often helps to reduce with PCA or UMAP before clustering.

13. The Full Recipe in Code

import numpy as np
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA
from sklearn.cluster import KMeans
from sklearn.metrics import silhouette_score

X = load_my_table()                       # rows x numeric columns, no labels

# 1. scale (distance-based methods need it)
Xs = StandardScaler().fit_transform(X)

# 2. reduce: keep enough components for 90% of the variance
pca = PCA(n_components=0.90, random_state=0).fit(Xs)
Z = pca.transform(Xs)
print("components kept:", pca.n_components_)

# 3. try several k, look at silhouette (and at the elbow of inertia)
for k in range(2, 11):
    km = KMeans(n_clusters=k, n_init=10, random_state=0).fit(Z)
    print(k, round(km.inertia_), round(silhouette_score(Z, km.labels_), 3))

# 4. fit the chosen k, then LOOK at examples from each cluster
km = KMeans(n_clusters=5, n_init=10, random_state=0).fit(Z)
for c in range(5):
    print(c, np.sum(km.labels_ == c), "rows")
    # print a few raw rows from cluster c and name the cluster yourself

Step 4 is not optional. The algorithm gives numbered groups; only a person looking at examples can say "cluster 3 is weekend shoppers who only buy on discount".

14. Common Pitfalls

  • Not scaling. The biggest-number column decides everything (ARI -0.002 in our run).
  • Choosing k by lowest inertia. Inertia always falls as k grows. Use the elbow, silhouette, and what the business can act on.
  • One random start. 42 of 100 random starts got stuck. Use k-means++ and several starts.
  • Using k-means on odd shapes. It only finds round-ish blobs. Try DBSCAN or HDBSCAN.
  • Feeding categories as numbers. City codes 1, 2, 3 are not "distances". One-hot encode them, or use a method built for categories.
  • Reading too much into a 2D picture. 2 PCA components kept only 28.5% of the digits' variance. t-SNE and UMAP distort distances.
  • Fitting the scaler or PCA on all data, then evaluating a model on part of it. When unsupervised steps feed a supervised model, fit them on the training split only, or you leak test data (see data leakage).
  • Trusting clusters without looking. A clean silhouette can still mean "split by country", which you already knew.

15. Practice Problems (with Solutions)

Problem 1: one k-means round

Points on a line: 1, 2, 3, 10, 11, 20. k = 2, starting centroids 1 and 20. Do one assign and one update. Then finish.

Solution

Assign: 1, 2, 3, 10 are closer to 1 (10 is 9 from 1 and 10 from 20). 11 and 20 go to 20 (11 is 10 from 1, 9 from 20). Update: c1 = (1+2+3+10)/4 = 4, c2 = (11+20)/2 = 15.5. Assign again: 10 is 6 from 4 and 5.5 from 15.5, so it moves to c2. Now c1 = 2, c2 = (10+11+20)/3 = 13.67. Assign again: 1, 2, 3 stay with 2; 10, 11, 20 stay with 13.67. Done: {1, 2, 3} and {10, 11, 20}.

Problem 2: inertia

Compute the final inertia from Problem 1.

Solution

Cluster 1 (centroid 2): 1 + 0 + 1 = 2. Cluster 2 (centroid 13.67): 3.67^2 + 2.67^2 + 6.33^2 = 13.44 + 7.11 + 40.11 = 60.67. Total about 62.7.

Problem 3: silhouette for one point

A point's average distance to its own cluster is 2. Its average distance to the nearest other cluster is 8. What is its silhouette? What if the numbers were swapped?

Solution

s = (8 - 2) / 8 = 0.75: well placed. Swapped: s = (2 - 8) / 8 = -0.75: it is much closer to another cluster and is probably in the wrong one.

Problem 4: PCA eigenvalues

A centered data set has covariance matrix [[4, 0], [0, 1]]. What are the components and how much variance does PC1 explain?

Solution

The matrix is already diagonal: x and y do not move together. The components are just the x axis (variance 4) and the y axis (variance 1). PC1 = x axis, explaining 4 / (4 + 1) = 80%.

Problem 5: how many components

The explained variance ratios of a PCA are 0.50, 0.20, 0.12, 0.08, 0.05, 0.03, 0.02. How many components do you need for 90%? For 95%?

Solution

Running totals: 0.50, 0.70, 0.82, 0.90, 0.95, 0.98, 1.00. 4 components for 90%, 5 for 95%.

Problem 6: choose a method

For each, pick k-means, DBSCAN/HDBSCAN, PCA, or Isolation Forest: (a) find unusual logins among millions of rows with 12 numeric features; (b) a delivery company wants exactly 8 service zones from customer coordinates; (c) GPS points of taxi pickups that form long, curvy clusters along roads plus lots of scattered noise; (d) a model is slow because it has 900 strongly related sensor columns.

Solution

(a) Isolation Forest: anomaly ranking over many features. (b) k-means with k = 8: you need a fixed number of compact zones, and each centroid is a natural depot spot. (c) DBSCAN or HDBSCAN: odd shapes and noise. (d) PCA: replace 900 related columns with the few components that keep most of the variance.
