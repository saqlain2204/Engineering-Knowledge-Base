Decision Trees, Random Forests & Gradient Boosting

For data in tables (rows and columns, like a spreadsheet), tree models are often the strongest tool you can use. They power fraud checks, credit scores, search ranking, and many Kaggle wins. This page builds them from zero: one tree by hand, then many trees voting (random forests), then many trees fixing each other's mistakes (gradient boosting). It continues from Classical ML from Zero, and every number comes from a run you can repeat.

1. The Idea: a Game of Twenty Questions

Think of a doctor deciding if a patient needs more tests. They might ask: "Is the fever above 39?" If yes: "Has it lasted more than 3 days?" Each answer sends you down one path. At the end of the path is a decision.

A decision tree is exactly this: a set of yes/no questions about the features, arranged like an upside-down tree.

                 hours studied <= 3.5 ?
                  /                 \
                yes                  no
                 |                    |
             FAIL (4/4)      slept 7+ hours ?   ... and so on

Intuition. A linear model draws one straight line through the data. A tree cuts the data into boxes, one question at a time, and gives each box its own answer. Boxes can follow odd shapes, like "young AND high income" or "old AND low income", which a single straight line cannot do.

The machine's job is to pick which questions to ask, and in which order. It does this greedily: at each step it picks the question that best separates the labels right now, without planning ahead.

2. The Words, in Plain English

WordPlain meaning

LeafAn end point with no more questions. It holds the answer (a class, or a number).
SplitA question that divides rows into a left group and a right group.
DepthHow many questions you answer on the longest path from root to leaf.

BoostingTrain models one after another; each new one focuses on the mistakes left by the ones before.
ResidualThe error that is left: true value minus current prediction.
HyperparameterA setting you choose before training (like max depth). It is not learned from data.

3. Picking a Split: Gini Impurity by Hand

We need a number that says "how mixed is this group?". The most common one is Gini impurity:

Gini = 1 - (p_pass)^2 - (p_fail)^2

Here p_pass is the share of rows in the group that passed. Some values:

Groupp_passGiniMeaning
4 pass, 0 fail1.01 - 1 - 0 = 0Pure. Nothing left to learn.
3 pass, 1 fail0.751 - 0.5625 - 0.0625 = 0.375Mostly one class
5 pass, 5 fail0.51 - 0.25 - 0.25 = 0.5Most mixed possible (for 2 classes)

A split is good if the two groups it makes are purer than the group before. We score a split by the weighted average Gini of the two sides (weighted by how many rows land on each side). Lower is better.

Worked example: ten students

We want to predict pass (1) or fail (0) from hours studied and whether the student slept 7+ hours.

H8yes1

J6no0

Step 1: Gini of the root. 5 passed, 5 failed, so p = 0.5 and Gini = 0.5.

Step 2: try every possible question. For a number feature, the tree tries cut points halfway between neighbouring values (1.5, 2.5, 3.5, ...). For a yes/no feature, there is only one question.

Take "hours <= 3.5?":

  • Left (yes): A, B, C, I. All 4 failed. Gini = 0.
  • Right (no): D, E, F, G, H, J. 5 passed, 1 failed. p = 5/6, Gini = 1 - (5/6)^2 - (1/6)^2 = 1 - 0.694 - 0.028 = 0.278.
  • Weighted: (4/10) × 0 + (6/10) × 0.278 = 0.167.

Doing this for every candidate gives (computed by the script in section 12):

hours <= 2.50 0 00 1 1 1 1 1 00.286

hours <= 4.50 0 0 1 01 1 1 1 00.320
hours <= 5.50 0 0 1 1 01 1 1 00.417

hours <= 7.50 0 0 1 1 1 1 0 010.444

Step 3: pick the lowest. "hours <= 3.5" wins with 0.167. The drop from 0.5 to 0.167 (= 0.333) is called the impurity decrease or gain. That becomes the root question.

Step 4: repeat on each side. The left side is already pure, so it becomes a leaf: "FAIL". The right side (D, E, F, G, H, J) still has one fail (J: 6 hours, did not sleep 7+). The tree now searches again, using only those 6 rows, and keeps going until the leaves are pure or a stopping rule says stop.

Other impurity measures. Entropy = -p log2(p) - (1-p) log2(1-p) is another choice; it gives almost the same trees. For regression (predicting a number), the impurity is the variance of the values in the group, and each leaf predicts the mean of its rows. We use that in section 7.

4. Growing the Whole Tree, and When to Stop

The full algorithm is short:

  1. Start with all training rows at the root.
  2. For every feature and every cut point, compute the weighted impurity of the split.
  3. Keep the best split. Send rows left or right.
  4. Repeat on each child, until a stopping rule is hit.
  5. Each leaf predicts the majority class (classification) or the mean value (regression) of its training rows.

If you never stop, the tree keeps splitting until every leaf is pure. Then it gets 100% of the training data right, including the noise and the odd cases. That is overfitting: it memorised, it did not learn. The common stopping rules (all are hyperparameters):

Setting (scikit-learn name)What it doesTypical values
max_depthStop when the path is this many questions long3 to 10 for a single tree
min_samples_leafEvery leaf must keep at least this many rows5 to 50; stops tiny "one odd row" leaves
min_samples_splitDo not split a node with fewer rows than this10 to 100
ccp_alphaPruning: grow fully, then cut back branches that add littleTune with cross-validation

Prediction is fast: a depth-10 tree answers at most 10 questions per row, whatever the size of the training data.

Read the table like this: as the tree gets deeper, the train score climbs to a perfect 1.000, but the test score peaks at depth 3 and then falls. A gap between train and test is the sign of overfitting. Here is the depth-2 tree scikit-learn learned:

|--- worst perimeter <= 106.10
|   |--- worst concave points <= 0.13  -> benign
|   |--- worst concave points >  0.13  -> malignant
|--- worst perimeter >  106.10
|   |--- worst concave points <= 0.14  -> malignant
|   |--- worst concave points >  0.14  -> malignant

A human can read it: "a big tumour outline, or many concave points, means malignant". That is the great strength of a single small tree.

Careful with small test sets. With 143 test rows, one row is 0.7 percentage points. So 0.916 vs 0.902 is only 2 rows. Do not trust small gaps from one split. Use cross-validation, as in section 9.

A single tree has a bigger problem than overfitting: it is unstable. Change a few training rows and the root question can change, and then the whole tree below it changes. In ML words, a deep tree has low bias (it can fit any shape) but high variance (it changes a lot with the data). The next two ideas fix this in two different ways.

6. Random Forests: Many Trees Voting

Idea: if one tree is noisy, train many different trees and let them vote. Their random mistakes cancel out. The real pattern, which they all see, remains.

Intuition. Ask one person to guess the number of sweets in a jar, and they may be far off. Ask 300 people and take the average, and you are usually very close. This only works if people make different mistakes. 300 copies of the same person give the same wrong answer.

So the trees must be different. A random forest makes them different in two ways:

  1. Bootstrap rows (bagging). Each tree trains on a sample of N rows drawn with replacement from the N training rows. Some rows appear twice, some not at all. On average a tree sees about 63% of the distinct rows, because the chance a row is never picked is (1 - 1/N)^N, which is about 1/e = 0.37.
  2. Random features at each split. At every node, the tree may only look at a random subset of features. For classification the default is the square root of the feature count: with 30 features, each split picks the best of about 5 random ones. This stops every tree from using the same strong feature at the root.
  training rows ──► sample 1 ──► tree 1 ──┐
                ──► sample 2 ──► tree 2 ──┤
                ──►   ...    ──►  ...   ──┼──► vote (or average) ──► prediction
                ──► sample T ──► tree T ──┘
  (each tree: deep, no pruning, random feature subset at every split)

Each tree is grown deep (it overfits on purpose). The vote removes the variance.

A free validation score: out-of-bag (OOB)

Each tree never saw about 37% of the rows. For each row, we can let only the trees that did not train on it vote. That gives an honest score without a separate validation set. It is called the out-of-bag score.

Adding more trees does not make a random forest overfit more; it only makes the vote more stable. The cost is time and memory. Past a few hundred trees the gain is usually tiny.

7. Gradient Boosting, Built by Hand

Random forests build trees side by side, independently. Boosting builds them one after another, and each new tree tries to fix what the trees before it got wrong.

Intuition. A golfer hits the ball toward the hole. It stops short. The next shot does not start from the tee; it starts from where the ball is and only covers the remaining distance. Each tree in boosting is one more shot, aimed at the remaining error (the residual).

The recipe for regression with squared error:

  1. Start with a flat guess: the mean of all labels. Call it F.
  2. Compute residuals: r = y - F for each row.
  3. Fit a small tree (often depth 1 to 6) to predict r from the features.
  4. Update: F = F + learning_rate × (the tree's prediction).
  5. Repeat steps 2 to 4 for T rounds.

Worked example: four houses

Size x (square metres) and price y (lakhs): (50, 100), (70, 150), (90, 170), (110, 260). Learning rate 0.5. Each tree is a "stump" (depth 1: one question).

Round 0. F = mean(100, 150, 170, 260) = 170 for every house.

Round 1.

  • Residuals: 100 - 170 = -70, 150 - 170 = -20, 170 - 170 = 0, 260 - 170 = 90.
  • Best stump on x (it tries cuts at 60, 80, 100): "x <= 100?". Left leaf = mean(-70, -20, 0) = -30. Right leaf = 90.
  • Update with rate 0.5: houses 1 to 3 get 170 + 0.5 × (-30) = 155. House 4 gets 170 + 0.5 × 90 = 215.
  • F = [155, 155, 155, 215]. Mean squared error (MSE) = ((-55)^2 + (-5)^2 + 15^2 + 45^2) / 4 = 1325.

Round 2.

  • Residuals: -55, -5, 15, 45.
  • Best stump: "x <= 60?". Left = -55. Right = mean(-5, 15, 45) = 18.33.
  • F = [155 - 27.5, 155 + 9.17, 155 + 9.17, 215 + 9.17] = [127.5, 164.17, 164.17, 224.17]. MSE = 568.8.

Round 3.

  • Residuals: -27.5, -14.17, 5.83, 35.83.
  • Best stump: "x <= 80?". Left = -20.83, right = 20.83.
  • F = [117.08, 153.75, 174.58, 234.58]. MSE = 243.2.

The error falls every round: 1325, then 568.8, then 243.2. No single stump could fit four prices, but the sum of small stumps can. That is boosting.

Why "gradient"? For squared error, loss = (y - F)^2 / 2. Its slope (gradient) with respect to F is -(y - F). So the residual y - F is exactly the negative gradient. Fitting a tree to residuals means taking a step downhill on the loss, like gradient descent, but each step is a tree instead of a change to a weight. For other losses (log loss for classification, absolute error, ranking losses), you fit the tree to that loss's negative gradient instead. The rest of the recipe is the same.

For classification, F is a score (log-odds). The predicted probability is sigmoid(F), just as in logistic regression.

The popular libraries

  • XGBoost, LightGBM, CatBoost: fast, well-tested gradient boosting. LightGBM grows trees leaf by leaf and is very fast on big data. CatBoost handles category columns (like city names) well.
  • scikit-learn HistGradientBoosting: the same ideas, built in. It first puts each feature into at most 255 bins (a histogram), so finding a split means scanning 255 bins instead of every unique value. This is why modern boosting is fast on millions of rows. It also handles missing values by itself.

Three lessons:

  1. Ensembles beat a single tree by about 3 to 4 points. That is the variance fix at work.
  2. Forest and boosting are close. On many tabular problems boosting wins by a little after tuning; a forest is harder to get wrong with default settings.
  3. The simple linear model wins here. On this dataset the two classes are separated almost by a straight line, and with only 569 rows, the simplest model that fits has the least variance. Always train a simple baseline first. Trees shine when the pattern has thresholds and combinations ("risky only if new account AND large amount AND night time").

10. Feature Importance and Its Traps

Tree models can tell you which features they used most. The default in scikit-learn is impurity-based importance: add up the impurity decrease of every split that used a feature, over all trees, then scale so all importances sum to 1. The top five in our 300-tree forest:

FeatureImportance
worst perimeter0.145
worst radius0.134
worst concave points0.121
worst area0.101
mean concave points0.100

Traps:

  • Correlated features share the credit. Perimeter, radius and area all measure tumour size. The forest splits the credit between them, so each looks less important than "size" really is. Drop two of them and the third would jump up.
  • Bias toward many-valued features. A column like a user ID has many possible cut points and can look important by chance. Impurity importance is computed on training data, so it rewards what the model memorised.
  • Importance is not cause. It says what the model used, not what changes the outcome in the real world.

A safer choice is permutation importance: shuffle one feature's column in the validation set and measure how much the score drops. If the score does not drop, the model did not really need that feature (sklearn.inspection.permutation_importance). For explaining one prediction at a time, SHAP values are the common tool.

11. When to Use Trees (and When Not)

SituationGood choiceWhy
Tabular data, mixed number and category columns, thresholds and combinationsGradient boosting (then random forest)Strong accuracy with little feature work; no scaling needed
Need a rule a human can read and checkOne small tree (depth 2 to 4)It is a flowchart
Few rows, roughly linear patternLogistic or linear regressionLeast variance, as in section 9
Images, audio, free textNeural networks (see Foundations and Transformers)Trees cannot learn useful features from raw pixels or words
Must predict outside the training range (prices next year are higher than ever before)Linear models, or trees on a target with the trend removedA leaf is an average of training values, so a tree can never predict above the highest value it has seen

Nice properties of trees: no need to scale features (a split "x <= 3.5" does not care about units), they handle missing values (modern libraries learn which side missing values should go), and they are fast to predict.

12. The Full Recipe in Code

The hand-worked Gini table and boosting rounds above come from this tiny script (plain Python, no libraries):

data = [(1,0,0),(2,1,0),(3,0,0),(4,1,1),(5,0,1),(6,1,1),(7,0,1),(8,1,1),(2,0,0),(6,0,0)]

def gini(ys):
    if not ys:
        return 0
    p = sum(ys) / len(ys)
    return 1 - p*p - (1-p)*(1-p)

for t in [1.5, 2.5, 3.5, 4.5, 5.5, 6.5, 7.5]:
    left  = [d[2] for d in data if d[0] <= t]
    right = [d[2] for d in data if d[0] > t]
    w = len(left)/10 * gini(left) + len(right)/10 * gini(right)
    print(f"hours <= {t}: weighted gini {w:.3f}")

# gradient boosting with stumps, by hand
x, y, lr = [50, 70, 90, 110], [100, 150, 170, 260], 0.5
F = [sum(y) / 4] * 4
for step in range(3):
    r = [a - b for a, b in zip(y, F)]
    best = None
    for t in [60, 80, 100]:
        L = [ri for xi, ri in zip(x, r) if xi <= t]
        R = [ri for xi, ri in zip(x, r) if xi > t]
        ml, mr = sum(L)/len(L), sum(R)/len(R)
        sse = sum((v-ml)**2 for v in L) + sum((v-mr)**2 for v in R)
        if best is None or sse < best[0]:
            best = (sse, t, ml, mr)
    _, t, ml, mr = best
    F = [f + lr * (ml if xi <= t else mr) for f, xi in zip(F, x)]
    mse = sum((a-b)**2 for a, b in zip(y, F)) / 4
    print(f"round {step+1}: split x <= {t}, F = {[round(v, 2) for v in F]}, MSE = {mse:.1f}")

And the model comparison (scikit-learn 1.9):

13. Common Pitfalls

  • Judging a tree by its training score. An unlimited tree always scores 100% on training data. Only validation or test scores count.
  • Leakage through a too-good feature. Trees find leaks fast: one split on a leaked column gives a pure leaf. If one feature has a huge importance and the score looks too good, check that the feature exists at prediction time (see Data Leakage).
  • Turning categories into numbers like 1, 2, 3. "City = 1, 2, 3" makes the tree think city 3 is "bigger" than city 1. Use one-hot columns (one yes/no column per city), or a library with built-in category support (LightGBM, CatBoost, or HistGradientBoosting with categorical_features).
  • Boosting without early stopping. A fixed, huge tree count slowly overfits. Keep a validation set and stop when it stops improving.
  • Tuning on the test set. Pick hyperparameters with cross-validation. Touch the test set once, at the end.
  • Expecting extrapolation. A tree predicting house prices will never predict above the most expensive house it saw.
  • Reading impurity importance as truth. Use permutation importance on validation data, and remember that correlated features split the credit.
  • Huge forests in production. 1000 deep trees can take hundreds of megabytes and be slow per request. Check model size and latency before you ship.

14. Practice Problems (with Solutions)

Problem 1: Gini of a group

A leaf has 8 rows: 6 "spam" and 2 "not spam". What is its Gini impurity?

Solution

p = 6/8 = 0.75. Gini = 1 - 0.75^2 - 0.25^2 = 1 - 0.5625 - 0.0625 = 0.375.

Problem 2: compare two splits

A node has 10 rows (5 yes, 5 no). Split A gives left (4 yes, 0 no) and right (1 yes, 5 no). Split B gives left (3 yes, 2 no) and right (2 yes, 3 no). Which split does the tree choose?

Solution

Split A: left Gini 0. Right: p = 1/6, Gini = 1 - 0.028 - 0.694 = 0.278. Weighted = 0.4 × 0 + 0.6 × 0.278 = 0.167.

Split B: each side has p = 0.6 or 0.4, so Gini = 1 - 0.36 - 0.16 = 0.48. Weighted = 0.48.

The tree picks split A (lower weighted Gini; gain 0.5 - 0.167 = 0.333).

Problem 3: one boosting round

Three rows have labels 10, 20 and 60. Learning rate 0.1. The first tree predicts the residuals perfectly. What is the prediction for each row after round 1?

Solution

Start F = mean = 30. Residuals: -20, -10, 30. The tree predicts exactly these. New F = 30 + 0.1 × (-20, -10, 30) = 28, 29, 33. With a small learning rate, each round only moves a little, so many rounds are needed.

Problem 4: forest or boosting?

Your team has one afternoon, no time to tune, and a tabular dataset of 50,000 rows. Which ensemble would you try first, and why?

Solution

A random forest with default settings (a few hundred trees). More trees do not make it overfit, and it works well untuned. Gradient boosting may score a bit higher, but it needs the learning rate, depth and early stopping set well. Also train a logistic regression baseline: it takes seconds and tells you how much the trees really add.

Problem 5: the suspicious importance

A churn model (will a customer leave?) has 0.99 validation AUC. Its top feature, with importance 0.71, is "days since last support ticket closed". What do you check?

Solution

Whether that feature is computed only from data before the prediction time. A common leak: customers who already left get a "close account" ticket, so the feature holds the answer. Recompute it as of the prediction date (a point-in-time value; see point-in-time joins) and train again. If AUC drops a lot, it was leakage.

Problem 6: bootstrap math

With 1,000 training rows, about how many distinct rows does one tree in a random forest see? How many are out-of-bag for that tree?

Solution

The chance a row is never picked is (1 - 1/1000)^1000, about 0.368. So about 368 rows are out-of-bag and about 632 distinct rows are used (some more than once, to make 1,000 picks in total).
