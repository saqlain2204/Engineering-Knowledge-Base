1. What Is Reinforcement Learning?

Reinforcement learning (RL) is the study of how an agent learns to act in an environment by trial and error to maximize cumulative reward. Unlike supervised learning, there is no fixed label for every input. The agent discovers which actions are good through feedback that may be delayed, sparse, or noisy.

The agent observes state $s_t$, takes action $a_t$, receives reward $r_{t+1}$, and transitions to $s_{t+1}$. The goal is to learn a policy $\pi(a|s)$ that maximizes expected discounted return.

Core vocabulary

Symbol / TermMeaning
$s, s'$State and next state
$a$Action
$r$Scalar reward signal
$\pi(a|s)$Policy: probability of action $a$ in state $s$
$P(s'|s,a)$Transition dynamics
$R(s,a,s')$ or $R(s,a)$Reward function
$\gamma \in [0,1)$Discount factor
$V^\pi(s)$State value under policy $\pi$
$Q^\pi(s,a)$Action-value under policy $\pi$
$A^\pi(s,a)$Advantage: $Q^\pi(s,a) - V^\pi(s)$

RL vs supervised vs unsupervised

  • Supervised: $(x, y)$ pairs; minimize prediction error.
  • Unsupervised: find structure in data without labels.
  • RL: sequential decisions; learn from scalar feedback and consequences of actions. Credit assignment (which past action caused later reward) is the central difficulty.
Intuition: RL is like learning chess by playing games, not by memorizing expert moves alone. You need both demonstrations (optional) and experience of winning/losing to internalize long-term strategy.

Refer: Sutton & Barto: Reinforcement Learning: An Introduction · A Brief Survey of Deep RL (Arulkumaran et al.)

2. Markov Decision Processes (MDPs)

An MDP is the standard mathematical framework for RL. It is a tuple $(\mathcal{S}, \mathcal{A}, P, R, \gamma)$:

  • $\mathcal{S}$: state space
  • $\mathcal{A}$: action space (discrete or continuous)
  • $P(s_{t+1}|s_t, a_t)$: transition kernel
  • $R(s_t, a_t, s_{t+1})$ or expected reward $R(s,a)$
  • $\gamma$: discount factor

Markov property

The future is independent of the past given the present:

$$P(s_{t+1}|s_t, a_t, s_{t-1}, \ldots, s_0) = P(s_{t+1}|s_t, a_t)$$
Intuition: The current state must summarize everything relevant for predicting the future. If it does not (e.g., a robot with limited sensors), you have a POMDP and typically maintain a belief state or use history / recurrent networks.

Episodic vs continuing tasks

  • Episodic: finite horizon ending in terminal states (games, robotics episodes).
  • Continuing: no terminal state; infinite horizon with discounting (resource allocation, perpetual control).

Partially Observable MDPs (POMDPs)

Agent receives observation $o_t$ from emission function $O(o|s,a)$, not full state. Solutions: stack observations, learn memory (RNN/Transformer), estimate belief $b(s)$, or treat observation as state (works if Markov in practice).

Policy types

  • Deterministic: $a = \mu(s)$
  • Stochastic: $\pi(a|s)$, required for exploration and policy gradient theory
  • Markovian: depends only on current state (or observation)

3. Returns, Discounting, and Value Functions

Return (cumulative reward)

$$G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots = \sum_{k=0}^{\infty} \gamma^k R_{t+k+1}$$
Intuition for $\gamma$: $\gamma$ near 0 makes the agent myopic (care about immediate reward). $\gamma$ near 1 makes it far-sighted. $\gamma < 1$ also guarantees bounded returns in continuing tasks and reflects uncertainty about future interactions.

State-value function

$$V^\pi(s) = \mathbb{E}_\pi[G_t \mid S_t = s] = \mathbb{E}_\pi\left[\sum_{k=0}^{\infty} \gamma^k R_{t+k+1} \mid S_t = s\right]$$

Action-value function (Q-function)

$$Q^\pi(s,a) = \mathbb{E}_\pi[G_t \mid S_t = s, A_t = a]$$

Advantage function

$$A^\pi(s,a) = Q^\pi(s,a) - V^\pi(s)$$

Advantage measures how much better action $a$ is than the average action under $\pi$ in state $s$. Policy gradients use advantages to reduce variance.

Optimal policy

$$\pi^* = \arg\max_\pi \mathbb{E}[G_t \mid \pi]$$

There exists an optimal policy that is deterministic (for MDPs) and satisfies $\pi^*(a|s) > 0 \iff Q^*(s,a) = \max_{a'} Q^*(s,a')$.

4. Bellman Equations: Derivation and Intuition

4.1 Bellman expectation equation for $V^\pi$

Start from the definition and split the sum at the first reward:

$$V^\pi(s) = \mathbb{E}_\pi[R_{t+1} + \gamma G_{t+1} \mid S_t = s]$$

Expand expectation over actions and next states under policy $\pi$:

$$\boxed{V^\pi(s) = \sum_a \pi(a|s) \sum_{s'} P(s'|s,a)\left[R(s,a,s') + \gamma V^\pi(s')\right]}$$
Intuition: The value of being in $s$ equals the expected immediate reward plus the discounted value of wherever you land next. This recursive structure is why dynamic programming works.

4.2 Bellman expectation equation for $Q^\pi$

$$\boxed{Q^\pi(s,a) = \sum_{s'} P(s'|s,a)\left[R(s,a,s') + \gamma \sum_{a'} \pi(a'|s') Q^\pi(s',a')\right]}$$

4.3 Bellman optimality equations

$$V^*(s) = \max_a \sum_{s'} P(s'|s,a)\left[R(s,a,s') + \gamma V^*(s')\right]$$ $$Q^*(s,a) = \sum_{s'} P(s'|s,a)\left[R(s,a,s') + \gamma \max_{a'} Q^*(s',a')\right]$$
Derivation sketch (optimality): At optimality, the agent picks the action maximizing expected return. Replacing $\pi(a|s)$ with $\arg\max_a$ in the expectation equation yields the Bellman optimality equation. $V^*$ and $Q^*$ are fixed points of these operators.

4.4 Relationship between $V$ and $Q$

$$V^\pi(s) = \sum_a \pi(a|s) Q^\pi(s,a), \quad Q^\pi(s,a) = \mathbb{E}[R + \gamma V^\pi(s') \mid s,a]$$ $$V^*(s) = \max_a Q^*(s,a), \quad \pi^*(s) = \arg\max_a Q^*(s,a)$$

5. Dynamic Programming (Model-Based Tabular)

When $P$ and $R$ are known, DP computes optimal policies without environment interaction. DP requires full sweeps over state space, feasible only only for small discrete problems but foundational for understanding RL.

5.1 Policy evaluation

Iteratively apply Bellman expectation until convergence:

$$V_{k+1}(s) = \sum_a \pi(a|s) \sum_{s'} P(s'|s,a)\left[R + \gamma V_k(s')\right]$$

Converges to $V^\pi$ as $k \to \infty$ (contraction mapping with modulus $\gamma$).

5.2 Policy improvement theorem

Define greedy policy w.r.t. $V^\pi$:

$$\pi'(s) = \arg\max_a \sum_{s'} P(s'|s,a)[R + \gamma V^\pi(s')]$$

Then $V^{\pi'}(s) \geq V^\pi(s)$ for all $s$, with strict improvement unless $\pi$ is already optimal.

Intuition: If you act greedily according to your current value estimates, you can only do better (or stay equal). You never forget what the old policy already achieved.

5.3 Policy iteration

  1. Evaluate $V^\pi$ (exactly or iteratively).
  2. Improve: $\pi \leftarrow \text{greedy}(V^\pi)$.
  3. Repeat until policy stable.

5.4 Value iteration

$$V_{k+1}(s) = \max_a \sum_{s'} P(s'|s,a)[R + \gamma V_k(s')]$$

Combines evaluation and improvement in one step. Extract policy after convergence: $\pi(s) = \arg\max_a \sum_{s'} P(s'|s,a)[R + \gamma V^*(s')]$.

# Tabular value iteration (toy example)
import numpy as np

V = np.zeros(n_states)
for _ in range(1000):
    V_new = np.zeros(n_states)
    for s in range(n_states):
        q_sa = []
        for a in range(n_actions):
            q = sum(P[s, a, sp] * (R[s, a, sp] + gamma * V[sp]) for sp in range(n_states))
            q_sa.append(q)
        V_new[s] = max(q_sa)
    V = V_new

6. Monte Carlo Methods

MC methods learn from complete episodes of experience. No bootstrapping: they use actual returns $G_t$ as targets.

6.1 MC prediction

Estimate $V^\pi(s)$ by averaging returns observed after visiting $s$:

$$V(s) \leftarrow \text{average of } G_t \text{ for all visits to } s$$

6.2 First-visit vs every-visit MC

  • First-visit: count return only at first occurrence of $s$ in episode.
  • Every-visit: count at every occurrence. Both converge to $V^\pi(s)$ under standard conditions.

6.3 MC control (on-policy)

Alternate policy evaluation and improvement using $\epsilon$-greedy exploration:

$$\pi(a|s) = \begin{cases} 1 - \epsilon + \frac{\epsilon}{|\mathcal{A}|} & a = \arg\max_a Q(s,a) \\ \frac{\epsilon}{|\mathcal{A}|} & \text{otherwise} \end{cases}$$

6.4 Off-policy MC and importance sampling

Learn about target policy $\pi$ from data collected by behavior policy $b$. Weight returns by likelihood ratio:

$$\rho_{t:T-1} = \prod_{k=t}^{T-1} \frac{\pi(A_k|S_k)}{b(A_k|S_k)}$$ $$V(s) = \mathbb{E}_b[\rho G_t \mid S_t = s]$$

Ordinary importance sampling is unbiased but high variance; weighted IS trades bias for lower variance.

7. Temporal-Difference Learning

TD methods bootstrap: update estimates using other estimates. They combine MC (learning from experience) with DP (bootstrapping).

7.1 TD(0) for prediction

$$V(S_t) \leftarrow V(S_t) + \alpha \left[R_{t+1} + \gamma V(S_{t+1}) - V(S_t)\right]$$

The term in brackets is the TD error:

$$\delta_t = R_{t+1} + \gamma V(S_{t+1}) - V(S_t)$$
Intuition: TD adjusts your prediction toward a one-step lookahead target. You do not wait for episode end. You learn online from partial trajectories.

7.2 SARSA (on-policy control)

$$Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha \left[R_{t+1} + \gamma Q(S_{t+1}, A_{t+1}) - Q(S_t, A_t)\right]$$

Named after tuple $(S, A, R, S', A')$. Learns the Q-values of the policy being followed (including exploration).

7.3 Q-learning (off-policy control)

$$\boxed{Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha \left[R_{t+1} + \gamma \max_a Q(S_{t+1}, a) - Q(S_t, A_t)\right]}$$

Uses max over next actions. It learns $Q^*$ while following an exploratory behavior policy (e.g., $\epsilon$-greedy).

Why Q-learning converges (tabular): The update is a contraction mapping on $Q$ toward the Bellman optimality operator. With sufficient exploration (every state-action pair visited infinitely often) and appropriate learning rate schedule, $Q \to Q^*$.

7.4 Expected SARSA

$$Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha \left[R_{t+1} + \gamma \mathbb{E}_{\pi}[Q(S_{t+1}, \cdot)] - Q(S_t, A_t)\right]$$

Lower variance than SARSA; intermediate between SARSA and Q-learning.

7.5 N-step returns

N-step return bridges 1-step TD and MC:

$$G_t^{(n)} = \sum_{k=0}^{n-1} \gamma^k R_{t+k+1} + \gamma^n V(S_{t+n})$$

N-step SARSA / Q-learning use $G_t^{(n)}$ as target. Larger $n$ → lower bias, higher variance.

7.6 TD($\lambda$) and eligibility traces

Bridge MC and TD with trace decay $\lambda \in [0,1]$:

$$G_t^{(\lambda)} = (1-\lambda) \sum_{n=1}^{\infty} \lambda^{n-1} G_t^{(n)}$$

Eligibility trace update: $E_t(s) = \gamma \lambda E_{t-1}(s) + \mathbf{1}(S_t = s)$. Combines credit assignment over multiple steps.

# Tabular Q-learning
import numpy as np

Q = np.zeros((n_states, n_actions))
for episode in range(num_episodes):
    s = env.reset()
    done = False
    while not done:
        a = epsilon_greedy(Q[s], eps)
        s_next, r, done, _ = env.step(a)
        Q[s, a] += alpha * (r + gamma * Q[s_next].max() - Q[s, a])
        s = s_next

8. Planning and Model-Based RL

8.1 Dyna-Q

Interleave real experience with simulated experience from a learned model $\hat{P}, \hat{R}$:

  1. Act in real env, update Q with Q-learning.
  2. Update model from transition $(s,a,r,s')$.
  3. Run $n$ planning steps: sample simulated transitions, update Q.

8.2 Monte Carlo Tree Search (MCTS)

Build a search tree via four steps per simulation:

  1. Selection: traverse using UCB1 until leaf.
  2. Expansion: add child nodes.
  3. Simulation: rollout to terminal or depth limit.
  4. Backpropagation: update visit counts and values.

UCB1 for action $a$ at node $s$:

$$\text{UCB1}(s,a) = Q(s,a) + c \sqrt{\frac{\ln N(s)}{N(s,a)}}$$

MCTS powered AlphaGo/AlphaZero. In LLMs, MCTS appears in reasoning-time search over token/action trees.

8.3 Model-based deep RL

  • World models (Dreamer, MuZero): learn latent dynamics, plan in imagination.
  • MBPO, PETS: use probabilistic models for sample-efficient control.
  • Tradeoff: model error compounds in long rollouts; short horizons + policy refinement work best.

9. Function Approximation and Deep RL

Tabular methods fail when $|S|$ or $|A|$ is huge or continuous. Approximate value or policy with parameterized functions $V(s;\mathbf{w})$, $Q(s,a;\mathbf{w})$, or $\pi(a|s;\boldsymbol{\theta})$.

9.1 Linear function approximation

$$V(s;\mathbf{w}) = \mathbf{w}^\top \mathbf{x}(s)$$

TD update: $\mathbf{w} \leftarrow \mathbf{w} + \alpha \delta_t \nabla_\mathbf{w} V(S_t;\mathbf{w})$. Convergence requires features $\mathbf{x}(s)$ that make the problem well-conditioned; divergence is possible with off-policy + bootstrapping (the deadly triad).

9.2 The deadly triad

Instability can arise from combining:

  1. Function approximation
  2. Bootstrapping (TD)
  3. Off-policy learning

DQN mitigates this with experience replay and target networks.

9.3 Deep Q-Network (DQN)

$$\mathcal{L}(\mathbf{w}) = \mathbb{E}_{(s,a,r,s') \sim \mathcal{D}}\left[\left(r + \gamma \max_{a'} Q(s',a';\mathbf{w}^-) - Q(s,a;\mathbf{w})\right)^2\right]$$
  • Experience replay: break temporal correlations, reuse data.
  • Target network $\mathbf{w}^-$: frozen copy updated periodically for stable targets.

10. Policy Gradient Methods

Directly optimize policy parameters $\boldsymbol{\theta}$ to maximize $J(\boldsymbol{\theta}) = \mathbb{E}_{\pi_\theta}[G_0]$.

10.1 Policy gradient theorem

$$\boxed{\nabla_\theta J(\boldsymbol{\theta}) = \mathbb{E}_{\pi_\theta}\left[\nabla_\theta \log \pi_\theta(A_t|S_t) \cdot Q^{\pi_\theta}(S_t, A_t)\right]}$$
Full derivation (policy gradient theorem):
  1. Objective: $J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta}[G_0] = \sum_\tau P(\tau;\theta) G(\tau)$ where $\tau = (s_0,a_0,r_1,\ldots)$.
  2. Gradient: $\nabla J = \sum_\tau \nabla P(\tau;\theta) G(\tau) = \mathbb{E}_\tau[\nabla \log P(\tau;\theta) \cdot G(\tau)]$ (likelihood ratio / log-derivative trick).
  3. Trajectory probability: $P(\tau;\theta) = p(s_0)\prod_{t=0}^{T-1} \pi_\theta(a_t|s_t) P(s_{t+1}|s_t,a_t)$.
  4. Log: $\log P(\tau;\theta) = \text{const} + \sum_t \log \pi_\theta(a_t|s_t)$; dynamics cancel.
  5. So $\nabla J = \mathbb{E}[\sum_t \nabla \log \pi_\theta(a_t|s_t) \cdot G_t]$. Using causality, future rewards before $t$ do not affect $a_t$, replace $G_t$ with $Q^{\pi_\theta}(s_t,a_t)$.

10.2 REINFORCE (Monte Carlo policy gradient)

$$\boldsymbol{\theta} \leftarrow \boldsymbol{\theta} + \alpha \gamma^t G_t \nabla_\theta \log \pi_\theta(A_t|S_t)$$

Use full return $G_t$ as unbiased estimate of $Q$. High variance.

10.3 Baseline for variance reduction

Subtract baseline $b(S_t)$ that does not depend on $A_t$:

$$\nabla J = \mathbb{E}\left[\nabla \log \pi(A_t|S_t) \cdot (G_t - b(S_t))\right]$$

Optimal baseline relates to value function. Using $b(S_t) = V(S_t)$ gives advantage-weighted update with the same expectation, lower variance.

Why baseline does not bias the gradient: $\mathbb{E}[\nabla \log \pi(A|S) \cdot b(S)] = b(S) \sum_a \nabla \pi(a|S) = b(S) \nabla \sum_a \pi(a|S) = b(S) \nabla 1 = 0$. 
# REINFORCE (PyTorch sketch)
log_probs = []
rewards = []
for t in range(T):
    dist = policy(s_t)
    a_t = dist.sample()
    log_probs.append(dist.log_prob(a_t))
    rewards.append(r_t)

returns = compute_discounted_returns(rewards, gamma)
loss = -sum(lp * G for lp, G in zip(log_probs, returns))
loss.backward()

11. Actor-Critic and Advantage Estimation

11.1 Actor-Critic architecture

  • Actor $\pi_\theta(a|s)$: policy
  • Critic $V_\mathbf{w}(s)$ or $Q_\mathbf{w}(s,a)$: value estimate for bootstrapping
$$\boldsymbol{\theta} \leftarrow \boldsymbol{\theta} + \alpha \nabla_\theta \log \pi_\theta(A_t|S_t) \cdot \delta_t$$ $$\delta_t = R_{t+1} + \gamma V(S_{t+1}) - V(S_t)$$

11.2 Generalized Advantage Estimation (GAE)

$$\delta_t = R_{t+1} + \gamma V(S_{t+1}) - V(S_t)$$ $$\hat{A}_t^{\text{GAE}(\gamma,\lambda)} = \sum_{l=0}^{\infty} (\gamma \lambda)^l \delta_{t+l}$$

$\lambda = 0$: one-step TD advantage (low variance, high bias). $\lambda = 1$: MC advantage (low bias, high variance). PPO uses GAE extensively.

GAE intuition: Exponentially-weighted sum of TD errors combines multi-step returns. $\lambda$ controls bias-variance tradeoff in credit assignment, critical for stable policy updates in robotics and LLM RLHF.

11.3 A2C / A3C

  • A2C: synchronous parallel workers, shared gradients.
  • A3C: asynchronous workers with Hogwild-style updates.

12. TRPO and PPO

12.1 Trust region motivation

Large policy updates can collapse performance. TRPO constrains KL divergence between old and new policy per update.

12.2 Surrogate objective (policy improvement lower bound)

$$L^{\text{CPI}}(\boldsymbol{\theta}) = \mathbb{E}_t\left[\frac{\pi_\theta(A_t|S_t)}{\pi_{\theta_{\text{old}}}(A_t|S_t)} \hat{A}_t\right] = \mathbb{E}_t\left[r_t(\boldsymbol{\theta}) \hat{A}_t\right]$$

where $r_t(\boldsymbol{\theta}) = \frac{\pi_\theta(A_t|S_t)}{\pi_{\theta_{\text{old}}}(A_t|S_t)}$ is the probability ratio.

12.3 TRPO constraint

$$\max_\theta L^{\text{CPI}}(\boldsymbol{\theta}) \quad \text{s.t.} \quad \mathbb{E}_t\left[\text{KL}(\pi_{\theta_{\text{old}}}(\cdot|S_t) \| \pi_\theta(\cdot|S_t))\right] \leq \delta$$

12.4 PPO-Clip objective

$$\boxed{L^{\text{CLIP}}(\boldsymbol{\theta}) = \mathbb{E}_t\left[\min\left(r_t(\boldsymbol{\theta}) \hat{A}_t, \; \text{clip}(r_t(\boldsymbol{\theta}), 1-\epsilon, 1+\epsilon) \hat{A}_t\right)\right]}$$
Intuition: If advantage is positive (good action), you want to increase $\pi_\theta(a|s)$ but not beyond ratio $1+\epsilon$. If advantage is negative, decrease but not below $1-\epsilon$. The pessimistic $\min$ prevents destructively large updates.

12.5 PPO full loss (typical implementation)

$$L = L^{\text{CLIP}} - c_1 L^{\text{VF}} + c_2 S[\pi_\theta](S_t)$$

Value loss $L^{\text{VF}} = (V_\theta(S_t) - V_t^{\text{target}})^2$, entropy bonus $S$ encourages exploration.

# PPO clipped objective (PyTorch)
ratio = (log_probs - old_log_probs).exp()
surr1 = ratio * advantages
surr2 = ratio.clamp(1 - eps, 1 + eps) * advantages
policy_loss = -torch.min(surr1, surr2).mean()

PPO is the default RL algorithm for RLHF in InstructGPT, many open-source alignment stacks, and robotics sim-to-real when sample budgets allow batch updates.

13. Continuous Control: DDPG, TD3, SAC

13.1 DDPG (Deep Deterministic Policy Gradient)

Off-policy actor-critic for continuous actions. Deterministic policy $\mu_\theta(s)$, critic $Q_\phi(s,a)$.

$$\nabla_\theta J \approx \mathbb{E}\left[\nabla_a Q_\phi(s,a)|_{a=\mu_\theta(s)} \nabla_\theta \mu_\theta(s)\right]$$

Uses replay buffer, target networks, and action noise for exploration.

13.2 TD3 (Twin Delayed DDPG)

  • Twin critics: take min of two Q estimates to reduce overestimation.
  • Delayed policy updates: update actor less frequently than critic.
  • Target policy smoothing: add noise to target actions.

13.3 SAC (Soft Actor-Critic)

Maximizes entropy-augmented objective:

$$J(\pi) = \sum_t \mathbb{E}\left[R_t + \alpha \mathcal{H}(\pi(\cdot|S_t))\right]$$

Soft Bellman backup:

$$Q(s,a) = \mathbb{E}\left[r + \gamma \left(V(s') + \alpha \mathcal{H}(\pi(\cdot|s'))\right)\right]$$

SAC is sample-efficient, stable, and widely used in robotics. Temperature $\alpha$ can be auto-tuned.

14. Multi-Armed Bandits

Bandits are RL without state: each pull of arm $a$ yields reward from distribution with mean $\mu_a$. The exploration-exploitation tradeoff is the core challenge.

14.1 Regret

$$R_T = T \mu^* - \mathbb{E}\left[\sum_{t=1}^T R_t\right], \quad \mu^* = \max_a \mu_a$$

Good algorithms achieve sublinear regret $R_T = o(T)$ so average regret per step $\to 0$.

14.2 $\epsilon$-greedy bandit

With probability $1-\epsilon$ pull $\arg\max_a \hat{\mu}_a$; else random arm. Simple but linear regret if $\epsilon$ fixed.

14.3 UCB1 (Upper Confidence Bound)

$$a_t = \arg\max_a \left[\hat{\mu}_a + \sqrt{\frac{2 \ln t}{N_t(a)}}\right]$$
Intuition: Optimism in the face of uncertainty. Arms with few pulls have large confidence bonus $\sqrt{2\ln t / N_t(a)}$, encouraging exploration. Hoeffding's inequality bounds the true mean within this interval with high probability. Pulling the upper bound maximizes expected best-case reward.

14.4 Thompson sampling

Maintain posterior $P(\mu_a | \text{data})$ (Beta for Bernoulli rewards, Gaussian for normal). Each step: sample $\tilde{\mu}_a$ from posterior, pull $\arg\max_a \tilde{\mu}_a$. Bayesian exploration: probability of exploring equals probability an arm could be optimal.

14.5 Contextual bandits

Context $x_t$ before each pull; reward $r \sim R(a, x_t)$. Linear UCB, LinTS, or neural bandits for personalization (ads, recommendations). LLM routing (pick model A vs B per query) is often a contextual bandit problem.

15. Exploration Strategies

  • $\epsilon$-greedy: simple, decay $\epsilon$ over time.
  • Softmax / Boltzmann: $\pi(a|s) \propto \exp(Q(s,a)/\tau)$.
  • UCB (bandits): optimism under uncertainty.
  • Thompson sampling: sample from posterior over rewards.
  • Intrinsic motivation: curiosity (prediction error), count-based bonuses, RND (Random Network Distillation).
  • Noisy networks, parameter noise: structured exploration in deep RL.

In LLM RL, exploration comes from stochastic decoding (temperature, top-p) during rollout collection.

16. Offline RL and Imitation Learning

15.1 Batch / offline RL

Learn purely from fixed dataset $\mathcal{D}$ without new environment interaction. Challenge: extrapolation error: Q-values for OOD actions are unreliable.

  • CQL (Conservative Q-Learning): penalize Q on OOD actions.
  • IQL (Implicit Q-Learning): expectile regression avoids querying max over OOD actions.
  • Decision Transformer: cast RL as conditional sequence modeling on return-to-go.

15.2 Imitation learning

  • Behavioral Cloning (BC): supervised learning on $(s, a)$ demos. Suffers covariate shift.
  • DAgger: iteratively query expert on states visited by learned policy.
  • GAIL: adversarial imitation: discriminator distinguishes expert vs policy trajectories; policy optimizes to fool discriminator (connection to inverse RL).

17. Advanced Topics

16.1 Multi-agent RL (MARL)

Multiple agents in shared or separate environments. Non-stationarity: other agents' policies change while you learn. Paradigms: independent learners, centralized training / decentralized execution (MADDPG), self-play (AlphaZero).

16.2 Hierarchical RL

Options framework: temporally extended actions (macro-actions). Feudal networks, HIRO: manager sets subgoals, worker executes.

16.3 Inverse RL and reward learning

Recover reward function $R$ from expert demonstrations. Maximum entropy IRL: experts maximize reward plus entropy. Foundation for GAIL and modern preference-based reward modeling in RLHF.

16.4 Meta-RL and transfer

Learn to adapt quickly to new tasks (MAML in RL, RL²). Relevant for multi-task LLM fine-tuning.

16.5 Safe RL and constrained RL

$$\max_\pi J(\pi) \quad \text{s.t.} \quad \mathbb{E}[C(s,a)] \leq d$$

Cost constraints $C$ for safety-critical robotics. Lagrangian methods, CPO. LLM analog: refusal constraints, toxicity budgets.

16.6 Distributional RL

Model full return distribution $Z(s,a)$ not just $\mathbb{E}[G]$. C51, QR-DQN, IQN for better risk-sensitive decisions.

19. Reward Design, Shaping, and Hacking

18.1 Reward function engineering

The reward defines the optimization target. Misspecified rewards lead to wrong behavior even with perfect RL algorithms.

18.2 Reward shaping

Add potential-based shaping to preserve optimal policy (Ng et al., 1999):

$$F(s,a,s') = \gamma \Phi(s') - \Phi(s)$$

Shaping function $\Phi$ guides learning without changing the optimal policy under standard conditions.

18.3 Sparse vs dense rewards

  • Sparse: +1 at goal only, hard exploration.
  • Dense: incremental feedback for easier learning but shaping bias risk.

18.4 Reward hacking / specification gaming

Agent maximizes proxy reward without achieving intended goal. Examples:

  • Boat racing agent loops for power-ups instead of finishing (CoastRunners).
  • Legged robot falls but thrashes to collect survival bonus.
  • LLM outputs verbose, sycophantic text to maximize learned reward model score.

18.5 Mitigations

  • Reward model ensembles and uncertainty penalties
  • KL constraints to reference policy (RLHF)
  • Human audits and adversarial eval sets
  • Process rewards vs outcome rewards
  • Verifiable rewards (unit tests, proof checkers) where possible
Goodhart's law in RL: When a measure becomes a target, it ceases to be a good measure. Any learned reward is a measure. Expect policies to exploit its blind spots.

20. Reinforcement Learning for Large Language Models

LLM post-training reframes text generation as sequential decision making: state = prompt + tokens so far, action = next token, policy = the language model.

19.1 Why RL for LLMs?

SFT fits demonstrations but cannot directly optimize human preferences, task success, or multi-objective tradeoffs. RL optimizes non-differentiable rewards: human ratings, win rates, code test pass rate, math verifier scores.

19.2 RLHF pipeline (InstructGPT / ChatGPT style)

  1. SFT on demonstrations.
  2. Reward model (RM) trained on preference pairs.
  3. RL fine-tuning (PPO) maximizing RM score with KL penalty to SFT reference.

19.3 Reward model training (Bradley-Terry)

Human prefers response $y_w$ over $y_l$ for prompt $x$. Model $r_\phi(x,y)$ scores completions:

$$P(y_w \succ y_l | x) = \sigma(r_\phi(x, y_w) - r_\phi(x, y_l))$$ $$\mathcal{L}_{\text{RM}} = -\mathbb{E}_{(x,y_w,y_l)}\left[\log \sigma(r_\phi(x,y_w) - r_\phi(x,y_l))\right]$$
Intuition: The RM learns a scalar utility function consistent with pairwise comparisons, like learning Elo ratings for chess players (responses) given match outcomes.

19.4 RLHF objective with KL penalty

$$\max_{\pi_\theta} \mathbb{E}_{x \sim \mathcal{D}, y \sim \pi_\theta(\cdot|x)}\left[r_\phi(x,y)\right] - \beta \, \mathbb{D}_{\text{KL}}\left[\pi_\theta(\cdot|x) \| \pi_{\text{ref}}(\cdot|x)\right]$$
Equivalent constrained form: Maximize reward subject to $\mathbb{D}_{\text{KL}} \leq \delta$. The Lagrangian gives the penalty form above with $\beta$ as dual variable. Prevents policy from drifting to high-RM-score gibberish far from the capable SFT model.

19.5 PPO for LLMs

Each token (or sequence chunk) is an action. Critic estimates value of partial sequences. Challenges:

  • Enormous action space ($|\mathcal{V}|$ ~ 50k–200k tokens)
  • Credit assignment across long generations
  • Reward often only at EOS (sequence-level RM score)
  • Four models in memory: policy, reference, critic, reward model

Practical tricks: reward normalization, KL in reward (not just loss), advantage whitening, response length limits, mixed batch SFT loss.

# RLHF-style training with TRL (conceptual)

    rewards = [reward_model(q, r) for q, r in zip(query_tensors, response_tensors)]

19.6 DPO: full derivation sketch

Under Bradley-Terry preferences, optimal RLHF policy satisfies:

$$\pi^*(y|x) = \frac{1}{Z(x)} \pi_{\text{ref}}(y|x) \exp\left(\frac{1}{\beta} r^*(x,y)\right)$$

Rearrange to express reward in terms of policies:

$$r^*(x,y) = \beta \log \frac{\pi^*(y|x)}{\pi_{\text{ref}}(y|x)} + \beta \log Z(x)$$

Substitute into preference loss; $Z(x)$ cancels in pairwise comparison:

$$\boxed{\mathcal{L}_{\text{DPO}} = -\mathbb{E}\left[\log \sigma\left(\beta \log \frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right)\right]}$$
Intuition: DPO directly increases log-odds of preferred vs rejected responses relative to the reference with no explicit RM or RL loop. Implicit reward is whatever makes preferences most consistent.

19.8 GRPO (Group Relative Policy Optimization)

Used in DeepSeek-R1 and modern reasoning RL. Sample group of outputs $\{y_1,\ldots,y_G\}$ per prompt, compute rewards $\{r_i\}$, normalize within group:

$$\hat{A}_i = \frac{r_i - \mathrm{mean}(r)}{\mathrm{std}(r) + \epsilon}$$

Apply PPO-style clipped loss on token log-probs with group-relative advantages. No separate critic network, which reduces memory vs classic PPO+value head.

19.9 REINFORCE / RLOO for LLMs

Leave-one-out baseline:

$$\hat{A}_i = r_i - \frac{1}{G-1}\sum_{j \neq i} r_j$$

Simpler than PPO; works well with verifiable rewards (math, code) where variance is manageable with enough samples.

19.10 Process Reward Models (PRM)

Score each reasoning step, not just final answer. Enables step-level credit assignment for chain-of-thought. Training data: human labels on intermediate steps. Inference: best-of-N or tree search guided by PRM.

19.11 Verifiable rewards (RLVR)

Domains with checkers: unit tests (code), symbolic math verification, formal proofs. Reward is deterministic function of output, which reduces RM hacking, enables scalable self-improvement (AlphaCode, DeepSeek-R1 style).

19.12 RLAIF and Constitutional AI

  • RLAIF: AI model labels preferences; scales cheaply, inherits labeler biases.
  • Constitutional AI: model critiques/revises outputs against principles; revisions become SFT/RL data.

19.13 Online RL and rejection sampling

Best-of-N sampling from policy, filter by reward, fine-tune on winners, simpler than full PPO. Iterative: generate → filter → SFT/DPO → repeat (ReST, RAFT).

19.14 Reward hacking in LLMs: specific patterns

  • Verbosity inflation: RM correlates length with quality.
  • Sycophancy: agreeing with user regardless of truth.
  • Format hacking: bullet lists, hedging phrases RM likes.
  • Refusal overfitting: excessive safety refusals to minimize penalty.
  • Reward model overoptimization: policy outpaces RM generalization (Goodhart).

19.15 LLM RL engineering checklist

  • Keep reference model frozen; monitor KL throughout training
  • Normalize rewards per batch; clip extreme advantages
  • Mix 5–10% SFT loss to prevent capability collapse (alignment tax)
  • Eval on held-out human prompts + capability benchmarks (MMLU, coding)
  • Track entropy: collapse indicates mode collapse / reward hacking

Refer: InstructGPT · DPO paper · DeepSeek-R1 / GRPO · Post-Training notes

20.2 Common failure modes

  • Value blow-up: reduce LR, clip rewards, check bootstrapping.
  • Policy collapse: entropy too low: increase entropy coef or temperature.
  • No learning: reward scale wrong, bugs in done masking, bad normalization.
  • RLHF regression: KL too low, RM overoptimization: increase $\beta$, refresh RM data.
