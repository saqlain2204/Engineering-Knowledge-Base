How it works

  • FCFS (first come, first served) runs processes in arrival order until each one finishes. Simple, but one long job makes everyone wait (the convoy effect).
  • SJF (shortest job first) picks the shortest waiting job when the CPU is free. It gives the lowest average waiting time when nothing can be interrupted, but long jobs can starve.
  • SRTF is SJF that can interrupt: a new job with less remaining time takes the CPU right away.
  • Round Robin gives each process one time quantum, then moves it to the back of the queue. Response time is good. A tiny quantum means many context switches.
  • Priority (non-preemptive here) picks the most important waiting job. Low-priority jobs can starve. Real systems fix this with aging.

Rules used here: ties go to the earlier arrival, then the lower ID. In Round Robin, a process that arrives at the same moment another one is preempted joins the queue first. Context switch cost is taken as zero, but the count is shown. Real Linux uses the EEVDF scheduler (since kernel 6.6), which mixes fairness with latency goals.

Things to try

  • Click "Convoy example" and compare FCFS with SJF. One long job first makes the average wait jump.
  • In Round Robin, set the quantum to 1, then to 8. Watch context switches and response time move in opposite directions.
  • Give one process a high priority number (low importance) and a late arrival. See how long it waits under Priority.
