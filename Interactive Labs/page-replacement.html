Page Replacement: FIFO vs LRU vs OPT

How it works

  • FIFO evicts the page that was loaded first. It ignores how often a page is used, so it can throw out a hot page.
  • LRU (least recently used) evicts the page unused for the longest time. Recent past predicts the near future. Real kernels approximate it, because exact LRU on every memory access is too slow. Linux uses MGLRU (multi-generational LRU) on many systems today.
  • OPT (optimal, also called Belady's algorithm) evicts the page whose next use is furthest in the future. It needs to know the future, so no real OS can run it. It is the best possible score, used as a yardstick.
  • LRU and OPT are stack algorithms: adding frames never adds faults. FIFO is not, which is why Belady's anomaly can happen.

Things to try

  • Load "Belady" and compare 3 frames with 4 frames for FIFO: 9 faults become 10.
  • Load "Loop" with 3 frames. LRU faults on every request, because the page it evicts is always the next one needed. This is why databases often use other policies for big scans.
  • Step one request at a time and read why each policy picked its victim.
