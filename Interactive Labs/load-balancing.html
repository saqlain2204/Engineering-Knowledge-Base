How it works

  • Round robin sends requests to servers in turn. It ignores how busy each server is, so the slow server gets the same share as the others and builds a long queue.
  • Random picks any server. Same problem, plus bad luck streaks.
  • Least connections sends each request to the server with the fewest requests in flight. A slow server keeps more in flight, so it gets fewer new requests.
  • Power of two choices picks two random servers and uses the less busy one. It gets most of the benefit of least connections without checking every server, which matters with many load balancers and thousands of backends.

Model: each server handles one request at a time in arrival order. Requests arrive at random (a Poisson process), and service times are random (exponential). The load balancer knows only in-flight counts, not server speed. Real proxies such as Envoy, NGINX and HAProxy offer all of these, and also weighted versions, retries and outlier detection that pulls a bad server out.

Things to try

  • Set slow servers to 0. All algorithms look alike at low load. Raise the load to 90% and watch random and round robin fall behind.
  • Keep one slow server at 5× and load at 70%. Round robin's p99 explodes. Least connections stays close to normal.
  • Set the slow server to 10× and press Play with round robin. Its queue grows without limit, because it gets more work than it can finish.
